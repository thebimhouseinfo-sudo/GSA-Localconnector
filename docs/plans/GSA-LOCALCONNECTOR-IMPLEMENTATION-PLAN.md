## Product constraints

- Complete and accept the full Mac experience at M5 before starting any P08 Windows feature work, native feasibility or detailed implementation design. Windows remains a later full target. Existing macOS/Windows/Ubuntu source CI is compatibility/regression evidence only, not parallel platform development or Linux product-host support.
- Explicit absolute working roots provide read/write/execute, including files, commands, Git and build/test. Reference roots provide list/search/read and copy-out into workspace only. No inferred parent, sibling, drive or other-host authority.
- Personal use has separate per-host plugins. Test the selected host individually; no simultaneous Mac+Windows, two-Mac, two-Windows or multi-machine matrix is required. This excludes a test requirement, not machines being online. Preserve multiple independent/concurrent projects on each host.
- No local reasoning agent, project Job creation/catalog or review/promote lifecycle. Process/run IDs identify actual execution and evidence only.
- No connector approval gate for allowed workspace operations. Authentication, content conflicts, root identity and OS boundary checks remain necessary. Network, dependency downloads and secrets require distinct explicit authorization.
- Toolchain access is a narrow execution-resource contract, not permission to read arbitrary `/Library`, home directories or other projects. Scripts, hooks and all descendants remain confined.
- Non-Git folders work offline with installed dependencies/toolchains. Local edits, commits and remote actions are distinct; repository/GSA policy applies at its own layer.
- Preserve user media and neighboring applications. Native experiments require scoped host execution and disposable fixtures; original disks are never test targets.

## Review focus and evidence

1. Mixed roots/aliases and project-content privilege escalation: P02/P03 test normalization, incompatible overlap and rejected widening atomically.
2. Reference data interpreted through scripts/imports/hooks: P01/P04 test interpreter entrypoints and read/eval limits, not just executable bits.
3. Replacement/revocation while descendants outlive parents: P02/P04/P06 test identity, ownership and revalidation, not only cwd.
4. User edits during capture/output/retry: P03/P05/P06 test conflicts, pinned provenance and uncertain effects without replay.
5. Concurrent projects on one selected host: P07, then P08 only after M5 acceptance, test per-host scope/controller safety, project isolation, lifecycle and neighbor preservation. No simultaneous multi-machine fixture is required.

Each task records criterion/task IDs, exact commit plus dirty-path hashes, timestamp, host OS/version/architecture, backend/toolchain/policy identity, scope/controller revisions, command/exit or errors, expected/actual observations, redacted log/artifact hashes and gaps. Source tests, native workload proof and live-plugin proof are separate. Relevant changes invalidate affected claims.

Verification starts with the targeted changed contract tests and build; reuse unchanged valid evidence. Run a broader source suite only when affected integration warrants it, and report skips/failures. Native tests require the real target host and disposable roots. A schema, method, compile, candidate policy or source-CI pass cannot replace end-to-end evidence.
