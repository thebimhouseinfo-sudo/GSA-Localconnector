## Small v2 wire contract

One new pure module, `src/hosts/macos-directory-provenance.ts`, proposes these names. Existing `DirectoryTreeBuild` and `DirectoryTreeBinding` remain the exact schemas in `macos-directory-evidence.ts`; no weakening or v1 rewrite.

```ts
type ReaderCaseId =
 "workspaceCapture"|"referenceCapture"|"unsafeSymlink"|"unsafeHardlink"|
 "unsafeSpecial"|"depthAt"|"depthOver"|"entriesAt"|"entriesOver"|
 "bytesAt"|"bytesOver"|"staleBinding"|"ungrantedPath"|"invalidWriteRequest"|
 "relocation"|"invalidUtf8Name"|"mountBoundary"|"sourceChange"|
 "directoryReplaceBeforeOpen"|"directoryReplaceDuringEnumeration";
type BlobRef = {sha256:string;bytes:number};
type ReaderCoverage = {case:ReaderCaseId;status:"OBSERVED"|"MISSING"|"UNAVAILABLE";
 observation_sha256:string|null;reason:string};
type ReaderProvenanceResult = {readerQualified:boolean;missing:ReaderCaseId[]};
```

`DirectoryReaderProvenanceV2` exact top-level fields are `format:"gsa-directory-tree-provenance-v2"`, `build:DirectoryTreeBuild`, `candidate:{release:BlobRef,source:BlobRef,build_record:BlobRef}`, `fixtures`, `observations`, `coverage`, `history`, `exclusions`, `unresolved`. Candidate blob hashes must match build release/source pins and parsed build record exactly; normalized-code provenance still needs the archived audited build/signature observations. No caller-supplied required-case list, qualification flag, file path or user-selected schema. Reject unknown fields, duplicate keys in JSON, accessors/prototypes in in-memory input and unknown enum members. `coverage` contains each of the 20 fixed case IDs exactly once, including unavailable cases. It is not a new product criterion: it spells out existing Task 4 reader cases and the accepted depth16/entry1024/8,388,608-byte boundaries. Manifest/response caps remain checked by existing capture validation.

- Each fixture has exact fields `id` (lowercase SHA256 of its canonical metadata excluding `id`), `build:DirectoryTreeBuild`, `stage`, `stageIdentity`, `hostRelease`, `arch`, `owner_fd:3`, `roots`, `outsideCanaries`, `artifacts`, `original_result:BlobRef`, `driver:BlobRef`, `audit:BlobRef`. Stage/root paths are historical labels only. `roots` has its own workspace/reference bindings, role/revision/device/inode and all three signed artifact digests, presign release digest and normalized code digest. Disjoint roots/canaries and fixed read-only signing profile follow v1; each fixture's build/host must equal index build. `artifacts` has one record per root, exact fields `{root_id,executable:BlobRef,info:BlobRef,codeResources:BlobRef,entitlements:BlobRef,verification:BlobRef}`; executable/Info/CodeResources bytes must match that root's artifact pins, and archived entitlement/signature verification must bind the same root/build. Absent records cannot be inferred from success text.
- Each observation has exact fields `sha256` (canonical metadata digest excluding `sha256`), `case`, `fixture_id`, `root_id`, `request:BlobRef`, `response:BlobRef`, `stderr:BlobRef`, `execution:BlobRef`, `ordering:BlobRef|null`, `audit:BlobRef`. Execution records identify closed helper PID, parent/birth/executable/artifact identity, operation and observed exit/signal/output truncation. Raw request binding must equal the referenced fixture's own root/role/revision/device/inode (except the explicit stale-revision denial). Response envelope/payload and expected case predicate are parsed from raw bytes, not trusted duplicated summaries. No receipt may be rebound to another fixture/root, and an observation's case must match its coverage entry.
- `history` is a nonempty list of `{result:BlobRef,audit:BlobRef,gaps:ReaderCaseId[]}` retaining original result bytes and their known missing facts. `exclusions` must contain the known incident report digest plus reason `UNAUDITABLE_NATIVE_TEST_INCIDENT`; hashes of any known incident outputs are excluded too. `unresolved` lists `{case:ReaderCaseId|null,reason:string,evidence:BlobRef|null}`. Historical gaps remain visible even after closure: a closure is coverage pointing to a sufficient independently audited new observation, never deletion/editing of original history. Required gap omissions or unexplained disappearance between reviewed revisions reject; first migration must preserve the reviewed historical gap inventory explicitly.

Pure API: `validateDirectoryReaderProvenance(index:unknown, build:DirectoryTreeBuild, blobs:ReadonlyMap<string,Uint8Array>):ReaderProvenanceResult`. It accepts bytes only, performs no filesystem/process/native I/O, and requires all referenced blobs present with exact length/hash. Malformed, contradictory or substituted evidence throws `SECURITY_BLOCKED`; well-formed incomplete evidence returns `readerQualified:false` plus all missing case IDs. MISSING/UNAVAILABLE entries have null observation and a nonempty reason. OBSERVED means a valid audited case, not a whole-reader PASS. All 20 cases must independently qualify for `readerQualified:true`; extra unrelated reader cases cannot compensate.

Canonical metadata uses UTF-8 JSON with a fixed field order specified by the typed constructors, no insignificant whitespace, no floats except finite observed monotonic ordering values. Digests are lowercase SHA256; counts/lengths safe nonnegative integers; bindings reuse decimal-string identities. A raw blob is never rewritten to become canonical. Original JSON remains byte-for-byte archived; canonicalization applies only to new index metadata. Exact constructor field order and per-case expected response/ordering schemas must be finalized in the source-only implementation plan before code; absent definitions mean NOT_READY for implementation.

Relocation retains v1's actual observed `stopConfirmed < parentRelocated < resumed < responseObserved`, same process birth/FD/parent identity and denied response/no outside content. Partial/synthetic/reconstructed timelines do not qualify. Source change and both replacement windows require audited actual ordering and release-process identity with the response, not an uncontrolled race or test-build-only instrumentation. Invalid-name and mount cases require actual helper boundary observations on a supporting fixture; EILSEQ/missing mount remains UNAVAILABLE and blocks reader qualification. No automatic mounting or OS permission change.
