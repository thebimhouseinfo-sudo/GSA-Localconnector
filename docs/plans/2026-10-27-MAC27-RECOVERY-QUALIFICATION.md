The constructed states are STRUCTURAL_READBACK_ONLY, not crashes. RLIMIT_FSIZE is WRITE_INTERRUPTION, not fsync failure or a post-capture crash. All namespaces, source/captured identities, file modes and independent workspace/reference/recovery/outside canaries are checked before/after the relevant operation. Late external writers may modify a captured inode as explicitly allowed by the approved progression plan; no immutable-snapshot/CAS requirement is added.

The post-capture observer must be prestarted and phase-gated; the existing `test-tree-broker.py` generic watch cannot be used unchanged for this case because the original/captured inode is already held during the earlier source read. Before any signal, the new test-only watch first requires the captured NAME to exist with the expected original device/inode, then revalidates same owned PID/birth/executable AND a matching held vnode FD. A matching FD alone is never eligible. Reserve one observer process for this watch, not a chain of restarted watchers. It has one fixed monotonic deadline (at most5.5 seconds), at most2000 polling iterations, at most one STOP event and one bounded receipt; no loop reset, resampling attempt or production delay. After the gate succeeds and STOP is sent, the independent confirm observer and driver perform fresh authoritative AFTER-STOP captured-name identity, source absence and staged-name presence/identity checks against the same frozen transaction; a pre-stop polling hit alone never qualifies the interruption. The six-process observer budget remains identity/watch/confirm for relocation and identity/phase-gated-watch/confirm for interruption. No production syscall wrapper, debug protocol or candidate instrumentation is introduced for observing this production crash case. If the broker already published/exited or the stop/phase cannot be independently confirmed, record INCONCLUSIVE and stop the suite; never relabel a constructed state as that crash. The diagnostic source is generated from the frozen production bytes with exactly one checked substitution at the post-capture sync-failure branch, compiled separately and hash-pinned; production source remains unchanged and gains no runtime debug flag. A separate disposable diagnostic installation/recovery root uses the same copied BASE signed bundles (same workspace/reference roots), one separately signed diagnostic recovery bundle and separate protected journal. Its receipts are DIAGNOSTIC_ONLY; no validator may use them to certify production code containment. All diagnostic inputs/substitution bounds and both installations must be prepared before the first broker. Existing coordinator deterministic store-create/update/transport-failure evidence is reused unless source changes invalidate it. Actual kernel fsync failure and physical power-loss durability remain untested limitations rather than manufactured results.
