# Generate image and save into a local GSA workspace

Use this skill only for a real request to save an actual image into a local, explicitly authorized workspace. A generated image displayed in chat is NOT proof it exists on the user's Mac. Image generation and local file writes are separate operations; never claim one implies the other.

## Ordered workflow

1. Resolve the user-stated local folder and desired image file name. Call `gsa-lc-mac.connector_status`, `list_workspaces`, and `list_capabilities`. Match an already registered workspace to the intended local folder, using its current ID; do not invent IDs or assume the chat sandbox path is a Mac path. Avoid calling `bind_workspaces` again when an appropriate grant exists. If the intended folder has not been explicitly granted, request/select only that root as directed by the user; note that a new grant may require signed Recovery before file writes. Reference/read-only roots never become writable implicitly.
2. Generate or edit the requested image using the available image-generation tool. Keep the exact resulting file bytes; never treat a visually similar placeholder, procedural test picture, screenshot, link label, preview, or an imagined file as the original image.
3. For a new image, use an exclusive relative filename with a matching `.png`, `.jpg`/`.jpeg`, or `.webp` extension. No absolute path in the MCP `path` field; workspace root is chosen by `workspace_id`. Do not overwrite existing assets. If updating an existing asset is requested, the current version requires a separate explicit hash-guarded update flow; `import_image_file` only creates new files.
4. If `fileBackendAvailable`, `fileWriteBackendAvailable` are true, `fileGrantSyncState` is `CURRENT`, and `import_image_file` is exposed in the connected app catalog, acquire an exclusive controller with `acquire_control`. Call `import_image_file({workspace_id, path, file, control_token})` with the REAL generated/selected image as the `file` input supplied by the ChatGPT host's `openai/fileParams` mechanism. Do not manually fabricate `file_id`, `download_url`, MIME type, signed URL or a `sandbox:` path. Host file inputs contain `download_url`, `file_id` (and optional `mime_type`/`file_name`); the server validates a trusted HTTPS origin, max 8 MiB and actual image bytes before using the signed native create-exclusive backend.
5. **Direct import is mandatory first.** If the Mac backend lists `import_image_file` but this ChatGPT session does not expose the callable tool, classify `CATALOG_NOT_REFRESHED`, **not** `IMPORT_UNAVAILABLE`. The MCP backend's `list_capabilities` does not prove that the ChatGPT host has approved/published the tool. Attempt the host's authorized Plugins app **Refresh** / MCP **Rescan** and activate the updated action where available; start a new chat with the app selected and check the callable inventory again. Do not bypass app review, invent a call to an unexposed tool or claim a local write. When the tool is visible, always try it with the real host-provided generated file before any Base64 fallback.
6. **Evidence-based fallback only:** Use `create_file_bytes` only after a documented failed direct attempt caused by real host fileParam unavailability, **or** after a confirmed tool-catalog snapshot still omits the importer and no supported Refresh/Rescan can be completed in the current session. Record the precise cause as `FILEPARAM_UNAVAILABLE` or `IMPORT_TOOL_NOT_EXPOSED` and call Base64 a **fallback**, never the intended normal route. It is valid only when the exact original ImageGen file bytes are independently accessible and their COMPLETE canonical Base64 can be passed in one genuine tool call (8 MiB maximum). Never truncate Base64, substitute SVG/procedural images, re-encode without user permission, mistake an image preview for bytes, or upload the image to an external service as a workaround. If no valid byte transfer is possible, report `BLOCKED` rather than an alleged save.
7. Independently verify with `get_file_info({workspace_id,path})` followed by `fetch_file_bytes({workspace_id,path})`. Compare SHA-256 and byte length with the imported source bytes/hash. For `import_image_file`, compare `source_sha256` with the file-info and fetch results. For Base64, compare original and fetched canonical Base64 (and digest). On conflict, mismatch, unknown transaction, missing file, or readback failure, report NOT VERIFIED; do not report PASS.
8. Release `control_token` in `finally`, including error paths. Report the exact local Mac path, relative name, dimensions if grounded, bytes, and verified SHA-256 only after successful readback. For a batch, track PASS/BLOCKED for each image; do not upgrade partial completion to full batch PASS.


## Verified capability versus live host availability

- **VERIFIED on a real Mac:** `create_file_bytes` wrote a procedural PNG under an already authorized Test workspace; `get_file_info` / `fetch_file_bytes` returned identical original bytes and SHA-256. This establishes native write/readback, **not** ImageGen transfer.
- **VERIFIED in macOS CI:** `import_image_file` advertises the official four-property ChatGPT file schema with `_meta["openai/fileParams"]=["file"]`, and a simulated file-object download can be imported with exact readback. Simulation does not establish a host-generated image handoff.
- **OBSERVED in an existing ChatGPT session:** backend `list_capabilities` can name `import_image_file` while the ChatGPT model-facing action inventory omits it. Treat this as **catalog/approval mismatch**, not proof that ImageGen images cannot be imported. A plugin Skill release does not itself refresh an App's MCP action snapshot.
- **PENDING:** actual ImageGen-generated PNG file passed via the ChatGPT host to `import_image_file` and hashed after writing on Mac. Never claim this is PASS until performed.

Successful direct import requires no Base64 text assembled by the model. The server can internally convert downloaded bytes to Base64 for its existing signed native mutation API; this internal transport implementation is **not** the model-facing Base64 workaround. Do not conflate the two.

## Security and error handling

- `REQUIRES_SIGNED_REINSTALL`, `FILE_GRANT_RECOVERY_REQUIRED`: stop. The user must quit the owner and apply a verified qualified signed Recovery. Do not use shell, direct host filesystem calls or arbitrary HTTP requests to bypass the native file backend. `bind_workspaces` cannot repair the signature on its own.
- Respect active control lease, exact role, pinned directory and grant revision. Use workspace tools, never raw local paths/OS commands as substitute file-write authority.
- `import_image_file` only downloads host-provided temporary file URLs from approved ChatGPT content origins; it does not retrieve arbitrary external image URLs and cannot be used to read Mac files outside a bound workspace. Do not disclose signed URLs, tokens, or Base64 in user-facing text.
- If the tool is not exposed yet because the Mac app has not been updated or the ChatGPT catalog has not refreshed, report that as a deployment/catalog limitation. Do not claim the plugin Skill alone added a working MCP tool.
- The tool's availability does not itself prove that a newly generated ImageGen file is offered via ChatGPT file params on every client. Only an actual host-mediated import followed by remote readback establishes end-to-end acceptance.
